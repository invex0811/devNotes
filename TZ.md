# DevNotes — ТЗ для Claude Code

Nov 19, 2026 · @Игорь Кеся

DevNotes — веб-приложение заметок для разработчиков игр и программ в духе Google Keep: идеи, баги и фиксы со статусами и метками, по проектам, с хранением в Google Таблицах пользователя и заполнением карточек через ИИ.

## Как работать по этому ТЗ

Ты, Claude Code, разрабатываешь DevNotes с нуля в пустом репозитории. Правила работы:

- **Язык.** С владельцем общайся по-русски. Интерфейс приложения на русском. Код, имена, комментарии и коммиты на английском.
- **Этапы.** Иди строго по разделу «Этапы разработки». После каждого этапа остановись, коротко напиши, что сделано и как это проверить, и жди подтверждения.
- **План.** Перед этапом 0 покажи короткий план и задай вопросы, если они есть.
- **Рамки.** Не добавляй функции, которых нет в ТЗ. Свои идеи перечисляй в конце отчёта по этапу.
- **Документация.** Используй актуальные стабильные версии библиотек. Перед работой с Google Identity Services, Sheets API, Drive API, Picker API и MCP SDK сверяйся с их документацией, а не с памятью.
- **Секреты.** Не проси ключи в чат. Значения лежат в `.env.local` (он в `.gitignore`) и в переменных репозитория GitHub.
- **Проверки.** Этап принят, когда проходят `npm run lint`, `npm run test` и `npm run build`. Для `packages/core` тесты обязательны.
- **Демо-режим.** Вся работа с Google спрятана за интерфейсом `DataStore`. Вторая реализация хранит данные в памяти и включается адресом `?demo=1`, чтобы приложение можно было разрабатывать и проверять без Google.
- **Макет.** К ТЗ приложены скриншоты макета. Поведение бери из текста, внешний вид из скриншотов и раздела «Дизайн». Если они противоречат друг другу, спроси.

## Продукт

Приложением пользуются независимые люди: каждый входит своим Google-аккаунтом и хранит заметки в своих таблицах. Сервера и общей базы данных нет, сайт статический.

| Понятие | Что это |
| --- | --- |
| Заметка | Карточка с заголовком и текстом. У неё один статус, любое число меток, цвет; её можно закрепить или убрать в архив. |
| Статус | Ровно один у заметки: «Новое», «В разработке», «Готово». |
| Метка | Сколько угодно у заметки. Встроенные: «Идея», «Баг», «Фикс». Пользователь создаёт свои, с названием и цветом. |
| Проект | Группа заметок: игра, программа, сайт. Каждый проект хранится в отдельной Google Таблице, которой можно поделиться. |
| Без проекта | Заметки вне проектов. Лежат в личной таблице пользователя. |
| Входящие | Вид: заметки, у которых нет ни одной метки. |
| На проверку | Вид: карточки, которые создал ИИ и которые пользователь ещё не подтвердил. |

## Хранение в Google Таблицах

У пользователя одна личная таблица и по одной таблице на каждый проект.

| Таблица | Название файла | Листы | Метка файла в Drive (`appProperties`) |
| --- | --- | --- | --- |
| Личная | DevNotes | `meta`, `notes`, `labels`, `projects` | `devnotes=home` |
| Проект | DevNotes — название проекта | `meta`, `notes`, `labels` | `devnotes=project` |

Личная таблица создаётся при первом входе. На новом устройстве приложение находит её через Drive `files.list` по `appProperties`.

### Папка на Диске

- **Папка DevNotes.** Все таблицы, которые создаёт приложение, лежат в папке «DevNotes» в корне Диска. Папку создаёт само приложение при первом входе и помечает `appProperties` `devnotes=folder`.
- **Создание таблиц.** Таблица создаётся сразу в папке: Drive `files.create` с `parents`, либо создание через Sheets API и перенос через `files.update`.
- **Поиск не зависит от папки.** Таблицы по-прежнему находятся по `appProperties` и по id из листа `projects`. Если пользователь перенёс таблицу в другое место, приложение её не теряет и обратно не возвращает.
- **Если папки нет.** Папка удалена или лежит в корзине: приложение создаёт новую при следующем создании таблицы.
- **Старые таблицы.** Таблицы, уже созданные в корне Диска, приложение один раз переносит в папку при входе.
- **Чужие проекты.** Общие проекты с `role=member` приложение не перемещает: файл принадлежит другому человеку. «Поделиться» открывает доступ только к таблице проекта, не к папке.

### Лист notes

| Колонка | Значение |
| --- | --- |
| `id` | UUID заметки |
| `title` | Заголовок, до 200 символов |
| `body` | Текст, до 20 000 символов, без разметки |
| `status` | `new`, `wip` или `done` |
| `labels` | JSON-массив названий меток, например `["Баг","Фикс"]` |
| `color` | `default`, `red`, `violet`, `green` или `yellow` |
| `pinned` | `TRUE` или `FALSE` |
| `archived` | `TRUE` или `FALSE` |
| `solution` | Текст поля «Как починил» |
| `source` | `user`, `ai_paste` (вставка от ИИ на сайте) или `ai_mcp` (создано через MCP-сервер) |
| `review` | `pending` для карточек на проверке, иначе пусто |
| `created_at`, `updated_at` | Время в ISO 8601, UTC |
| `deleted` | `TRUE` для удалённой заметки |

### Остальные листы

| Лист | Колонки |
| --- | --- |
| `meta` | `key`, `value`. Ключи: `schema_version` (сейчас 1), `kind` (`home` или `project`), `name` |
| `labels` | `name`, `color`, `created_at`. Только свои метки пользователя |
| `projects` | `id`, `name`, `spreadsheet_id`, `role` (`owner` или `member`), `order`, `added_at`, `removed` |

### Правила чтения и записи

- **Заголовки.** Первая строка листа содержит названия колонок. Колонки ищи по названию, а не по номеру.
- **Без формул.** Пиши с `valueInputOption=RAW`, читай с `valueRenderOption=UNFORMATTED_VALUE`. Текст, начинающийся со знака «=», не должен стать формулой.
- **Мягкое удаление.** Строки не удаляются, ставится `deleted=TRUE`. Так номера строк не сдвигаются.
- **Адрес строки.** При полном чтении листа строй карту «id → номер строки» и обновляй заметку по номеру. Если с последнего чтения прошло больше 60 секунд, перед записью перечитай колонку `id`: пользователь мог пересортировать таблицу вручную.
- **Новая заметка.** Добавляется через `values.append`, номер строки берётся из `updatedRange` в ответе.
- **Метки.** Сопоставляются по названию без учёта регистра. Встроенные есть всегда и в лист не пишутся. В боковой панели показывается объединение меток из всех таблиц; при разном цвете побеждает личная таблица.
- **Перенос между проектами.** Заметка добавляется в новую таблицу с тем же `id` и мягко удаляется в старой.

## Вход через Google и права доступа

Вход работает целиком в браузере через Google Identity Services, без своего сервера.

- **Область доступа.** Только `https://www.googleapis.com/auth/drive.file`. Она даёт доступ к файлам, которые приложение создало само или которые пользователь выбрал через Google Picker ([области Drive API](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)). Области `drive` и `spreadsheets` не запрашивай.
- **Токен.** Используй токен-модель: `google.accounts.oauth2.initTokenClient` и `requestAccessToken()`. Токен живёт недолго, браузер его не хранит, новый выдаётся по действию пользователя ([токен-модель GIS](https://developers.google.com/identity/oauth2/web/guides/use-token-model)). Держи токен только в памяти, не в `localStorage`.
- **Истечение токена.** При ответе 401 покажи плашку «Сессия истекла» с кнопкой «Продлить». Несохранённые правки ждут в очереди и не теряются.
- **Открытие сайта.** Сразу показывай заметки из кэша. Если токена нет, покажи кнопку «Войти через Google» (для вернувшегося пользователя «Продолжить»).
- **Первый вход.** Найди личную таблицу через `files.list`. Если её нет, создай с листами и заголовками.
- **Выход.** Кнопка «Выйти» отзывает токен и очищает локальный кэш. Если есть неотправленные правки, сначала предупреди.
- **Аккаунт в интерфейсе.** Имя и аватар показывай, только если их можно получить без новых областей доступа. Иначе достаточно надписи «Аккаунт Google».

### Общие проекты

1. Владелец нажимает «Поделиться» и вводит почту. Приложение выдаёт доступ к таблице проекта через Drive `permissions.create` с ролью `writer`.
2. Получатель в своём DevNotes выбирает «Подключить общий проект». Открывается Google Picker с фильтром по таблицам.
3. Приложение проверяет, что в выбранной таблице `meta.kind=project`, и добавляет её в лист `projects` с `role=member`.

Picker нужен потому, что с `drive.file` приложение не видит чужой файл, пока пользователь сам его не выберет. Правки других участников видны после очередного обновления, не мгновенно.

## Синхронизация и кэш

Заметки показываются из локального кэша мгновенно, а с таблицами приложение сверяется в фоне.

- **Запуск.** Сначала данные из IndexedDB, затем чтение всех таблиц: один запрос `values.batchGet` на таблицу.
- **Правки.** Изменение сразу попадает в интерфейс и кэш, затем в очередь записи. Очередь хранится в IndexedDB и переживает перезагрузку страницы.
- **Повторы.** При ошибке сети или ответе 429 запись повторяется с растущей паузой.
- **Набор текста.** Частые правки одной заметки объединяются: запись уходит через 0,8 секунды после последнего нажатия.
- **Конфликты.** Побеждает последняя запись заметки целиком, по `updated_at`. Если версия в таблице новее и локальных неотправленных правок нет, берётся версия из таблицы.
- **Обновление.** При возврате на вкладку, по кнопке «Обновить» и раз в 60 секунд для открытого общего проекта.
- **Без сети.** Чтение и правки работают из кэша, очередь уходит при появлении сети.
- **Недоступная таблица.** Если таблицу удалили или закрыли доступ, проект помечается как недоступный, кэш не стирается.

Индикатор внизу боковой панели показывает одно из состояний: «таблица синхронизирована», «сохраняю…», «нет сети, изменения сохранятся позже», «нужно продлить сессию».

## Функции приложения

### Заметки

- **Создание.** Поле быстрого ввода вверху экрана. Enter сохраняет заметку со статусом «Новое», введённый текст становится заголовком.
- **Диалог заметки.** Клик по карточке открывает диалог: заголовок, текст, статус, метки, проект, цвет, закрепление, архив, удаление. Сохранение автоматическое. Esc закрывает диалог.
- **Текст.** Одно обычное текстовое поле, без разметки и без отдельных блоков. Строки, начинающиеся с `[ ]` или `[x]`, показываются как пункты чек-листа и переключаются кликом.
- **Удаление.** Без окна подтверждения: всплывает сообщение «Удалено» с кнопкой «Отменить» на 5 секунд.
- **Архив.** Архивные заметки видны только в виде «Архив».

### Статусы и метки

- **Смена статуса кликом.** Клик по бейджу статуса на карточке переводит её по кругу: «Новое» → «В разработке» → «Готово» → «Новое». Заметку открывать не нужно.
- **Свои метки.** Можно создать, переименовать, перекрасить и удалить. Цвет выбирается из 8 готовых. Встроенные метки удалить нельзя.
- **Фильтры.** Клик по статусу или метке в боковой панели фильтрует заметки в текущей области. Повторный клик снимает фильтр. Счётчики считаются внутри области.

### Умный ввод

- **Метка по префиксу.** Если текст начинается с названия существующей метки и двоеточия («баг: …», «идея: …», «фикс: …»), метка ставится сама, а префикс убирается из заголовка. Для встроенных меток работают и `bug:`, `idea:`, `fix:`. Регистр не важен.
- **Подсказка.** Под полем видно, какая метка будет поставлена, ещё до сохранения.
- **Проект для заметки.** Ряд «В проект» под полем. По умолчанию выбран открытый проект, иначе «Без проекта».

### Проекты

- **Создание.** «Новый проект» в боковой панели открывает поле для названия. После создания для проекта заводится отдельная таблица, и пользователь сразу попадает в проект.
- **Область.** Клик по проекту показывает только его заметки. Есть области «Все заметки» и «Входящие». У каждого проекта виден счётчик заметок.
- **Перенос.** Кнопка «Проект» в диалоге заметки переносит её в другой проект.
- **Переименование и удаление из списка.** «Убрать из списка» скрывает проект в приложении, файл таблицы остаётся на Диске.
- **Общий проект.** Отмечен значком в списке. Кнопки «Поделиться» и «Подключить общий проект» работают так, как описано в разделе про вход.

### Сетка, доска, поиск

- **Сетка.** Адаптивная сетка карточек. Закреплённые идут первыми, остальные по дате создания, новые сверху (правка заметки карточку не двигает). На карточке: заголовок, до 4 строк текста, статус, метки, проект, дата.
- **Доска.** Три колонки по статусам для текущей области и фильтра. Перетаскивание карточки в другую колонку меняет статус. Переключатель «Сетка / Доска» в шапке.
- **Поиск.** Ищет по заголовку, тексту и полю «Как починил», без учёта регистра, по мере ввода, внутри текущей области.

### Баги и решения

- **Шаблон бага.** Когда метка «Баг» добавляется к заметке с пустым текстом, в текст подставляются строки «Что случилось:», «Как повторить:», «Ожидалось:». Это обычные строки того же текстового поля; на скриншоте диалога они лишь выделены для наглядности.
- **Поле «Как починил».** Показывается в диалоге, когда у заметки есть метка «Баг» и статус «Готово», либо когда поле уже заполнено.
- **Метка «Фикс».** При сохранении непустого решения к заметке добавляется метка «Фикс».
- **На карточке.** Если решение есть, карточка показывает его начало с подписью «Как починил».

### Выбор нескольких заметок

На карточке при наведении появляется флажок, на телефоне режим выбора включается долгим нажатием. Панель «Выбрано N» даёт три действия: «Скопировать для ИИ», «В архив», «Удалить».

### Телефон

Сайт работает от ширины 360 px. Боковая панель становится выезжающим меню, переключатель «Сетка / Доска» переезжает вниз, колонки доски листаются по горизонтали. Области нажатия не меньше 44 px.

## Работа с ИИ на сайте

Сайт обменивается с любым ИИ через буфер обмена: заметки копируются текстом, ответ ИИ вставляется и превращается в карточки. Сетевых запросов к ИИ сайт не делает.

### Скопировать для ИИ

- **Запуск.** Кнопка в шапке и в панели выбора. Открывает диалог со списком выбранных заметок и предпросмотром текста.
- **Формат текста.** Строка «Проект: …», строка-итог («Нужно исправить 2 бага и оценить 1 идею»), затем заметки: сначала баги, потом идеи, потом остальные. У каждой заголовок вида «БАГ 1. …», текст и, если есть, строка «Как починил: …».
- **Копирование.** Кнопка «Скопировать текст» кладёт текст в буфер и показывает подтверждение.
- **Код.** Сборка текста живёт в `packages/core` и покрыта тестами.

### Вставить от ИИ

Диалог из трёх шагов:

1. **Инструкция.** Кнопка «Скопировать инструкцию для ИИ» копирует готовый текст с описанием формата. Пользователь добавляет его к своему запросу в любом ИИ.
2. **Вставка.** Поле, куда вставляется ответ ИИ целиком.
3. **Предпросмотр.** Список распознанных карточек, выбор проекта и кнопка «Добавить на проверку (N)».

Формат, который должен выдать ИИ:

```json
{
  "devnotes": 1,
  "notes": [
    {
      "title": "Меню паузы не закрывается с геймпада",
      "body": "Что случилось: ...\nКак повторить: ...\nОжидалось: ...",
      "labels": ["Баг"],
      "status": "new",
      "solution": ""
    }
  ]
}
```

Правила разбора:

- **Поиск JSON.** Берётся первый блок кода `json` в тексте, а если его нет, первый JSON-объект.
- **Проверка.** Схема zod из `packages/core`. Обязателен только `title`. Неизвестный статус заменяется на `new`.
- **Новые метки.** Метки, которых ещё нет, создаются автоматически, но не больше 10 за одну вставку. Лишние отбрасываются с предупреждением.
- **Пределы.** Не больше 100 заметок за вставку, заголовок обрезается до 200 символов, текст до 20 000.
- **Ошибки.** Если ничего не распознано, диалог объясняет по-русски, что не так, и предлагает снова скопировать инструкцию.

### На проверку

- **Что сюда попадает.** Все карточки от ИИ: из «Вставить от ИИ» (`source=ai_paste`) и из MCP-сервера (`source=ai_mcp`). И те, и другие сохраняются с `review=pending`.
- **Видимость.** Пока карточка на проверке, её нет в сетке, на доске, в поиске и в счётчиках.
- **Пункт меню.** «На проверку» в боковой панели со счётчиком, под «Входящими».
- **Карточка.** Бейдж «От ИИ», проект, подпись источника («вставка от ИИ» для `ai_paste`, «через Claude Code» для `ai_mcp`), кнопки «Принять» и «Удалить». Текст можно поправить до принятия.
- **Массовые действия.** «Принять все» и «Удалить все», второе с подтверждением.
- **После принятия.** `review` очищается, `source` не меняется, заметка становится обычной. В её диалоге остаётся мелкая пометка «создано ИИ».

## MCP-сервер для Claude Code

MCP-сервер запускается на компьютере пользователя и даёт Claude Code читать и создавать карточки DevNotes. Сценарий: «найди баги в этом проекте и заведи карточки в DevNotes».

| Команда | Что делает |
| --- | --- |
| `list_projects` | Возвращает проекты пользователя: id и название, плюс «Без проекта» |
| `list_notes` | Заметки проекта с фильтрами `status`, `label`, `query`, `limit`. Без архивных и удалённых |
| `get_note` | Одна заметка целиком, включая решение |
| `create_notes` | Создаёт до 50 карточек в проекте. Всегда с `source=ai_mcp` и `review=pending` |
| `update_note` | Меняет статус, метки и решение у существующей заметки. Заголовок и текст не трогает |

Команд удаления и архивации нет. Обойти проверку через MCP нельзя: карточки из `create_notes` всегда попадают в «На проверку».

- **Пакет.** `packages/mcp`, транспорт stdio, формат данных и проверки из `packages/core`.
- **Подключение.** Пользователь сайта подключает сервер одной командой со страницы «Подключить Claude Code» на сайте: `claude mcp add --transport stdio --scope user devnotes -- npx -y <адрес сайта>/devnotes-mcp.tgz` (на Windows `cmd /c npx`), проверка через `claude mcp list` ([документация Claude Code по MCP](https://code.claude.com/docs/en/mcp)). Пакет — небольшой загрузчик: при каждом запуске он берёт свежую сборку сервера с сайта, а без сети запускает сохранённую копию. Для разработки остаётся `node /полный/путь/packages/mcp/dist/index.js`.
- **Вход.** Отдельный OAuth-клиент типа «Desktop app» в том же проекте Google Cloud, что и сайт, область `drive.file`. Первый вызов команды без входа открывает браузер; пользователь входит своим аккаунтом и повторяет просьбу. Команда `devnotes-mcp login` делает то же заранее.
- **Токены.** Refresh-токен хранится в папке настроек пользователя с доступом только для владельца. Client ID и secret Desktop-клиента встраиваются в пакет, который публикует сайт, из переменных репозитория `DEVNOTES_MCP_CLIENT_ID` и `DEVNOTES_MCP_CLIENT_SECRET` (Google не считает secret десктоп-клиента конфиденциальным). Переменные окружения и локальный файл настроек их переопределяют. В репозиторий значения не попадают.
- **Страница на сайте.** «Подключить Claude Code» в боковой панели: что даёт подключение, команда с кнопкой копирования для Windows и для macOS/Linux, проверка, примеры просьб, как отключить. Если владелец сайта не завёл переменные Desktop-клиента, страница объясняет, что подключение не включено.
- **Описания команд.** На английском, подробные: когда вызывать, какие поля обязательны, что карточки уйдут на проверку пользователю.
- **Документация.** `docs/MCP.md` на русском: установка, вход, подключение, примеры запросов.
- **Тесты.** Модульные, с подменой клиента Sheets API.

**Риск, который надо проверить первым на этом этапе.** Документация Google не говорит прямо, видит ли десктоп-клиент с `drive.file` таблицы, созданные веб-клиентом того же проекта Google Cloud. Проверь это на практике до написания команд. Если не видит, остановись и предложи владельцу варианты, не выбирай молча.

Тёмный сдержанный интерфейс с одним салатовым акцентом; внешний вид повторяет приложенные скриншоты макета.

| Панели, поля, диалоги | `#171A21` |
| Карточка | `#1A1E26` |
| Граница / разделитель | `#2A2F3A` / `#232833` |
| Текст / вторичный / приглушённый | `#E8EAF0` / `#B4BCCB` / `#9AA3B2` |
| Акцент и текст на нём | `#C6F04D` и `#10130A` |
| Статусы: новое / в разработке / готово | `#AEB8CC` / `#F5B544` / `#5BD68A` |

## Этапы разработки

Восемь этапов, каждый заканчивается остановкой и проверкой владельцем. Первые два не требуют настройки Google.

| Этап | Что делаем | Готово, когда |
| --- | --- | --- |
| 0. Каркас | Монорепозиторий, линтер, тесты, CI, публикация на GitHub Pages, пустая оболочка с тёмной темой | Сайт открывается по адресу Pages, проверки проходят в CI |
| 1. Заметки в демо-режиме | Типы и схемы в `core`, хранилище в памяти, сетка, быстрый ввод с умными метками, диалог заметки, статусы, метки, цвет, закрепление, архив, поиск, проекты, фильтры | Всё работает по адресу `?demo=1` без Google |
| 2. Google | Вход, создание личной таблицы, хранилище на Sheets API, кэш, очередь записи, индикатор | Заметка с сайта видна в таблице и на втором устройстве; правка без сети уходит после её появления |
| 3. Проекты и общий доступ | Отдельная таблица на проект, перенос заметок, «Поделиться», подключение общего проекта через Picker | Второй аккаунт подключает проект и видит правки первого |
| 4. Доска и баги | Доска с перетаскиванием, шаблон бага, «Как починил», выбор нескольких заметок, «Скопировать для ИИ» | Перетаскивание меняет статус в таблице; решение находится поиском |
| 5. ИИ на сайте | «Вставить от ИИ», вид «На проверку» | Ответ ИИ в заданном формате превращается в карточки, которые можно принять или удалить |
| 6. MCP-сервер | Проверка риска с `drive.file`, вход, пять команд, `docs/MCP.md` | Claude Code создаёт карточку, и она появляется в «На проверку» на сайте |
| 7. Телефон и полировка | Адаптив, доступность, манифест для установки на телефон, README, `docs/SETUP_GOOGLE.md` | Все экраны удобны на ширине 360 px; новый человек настраивает проект по документации |

## Что не входит в первую версию

Это не делаем сейчас, но архитектура не должна этому мешать:

- Подключение к сайтам claude.ai и ChatGPT (удалённый MCP-сервер с хостингом).
- Картинки и вложения в заметках.
- Совместное редактирование в реальном времени.
- Светлая тема.
- Версии и чейнджлог, статистика, ссылки между заметками, подсветка залежавшихся заметок, командная строка по Ctrl+K.
- Разметка Markdown и подсветка кода.
- Языки интерфейса, кроме русского.

## Ручные шаги владельца

Эти шаги владелец делает сам перед этапом 2. На этапе 2 ты пишешь по ним подробную инструкцию `docs/SETUP_GOOGLE.md` на русском и сверяешь её с текущим интерфейсом Google Cloud.

1. Создать проект в Google Cloud.
2. Включить Google Sheets API, Google Drive API и Google Picker API.
3. Настроить экран согласия OAuth: тип External, область `drive.file`.
4. Перевести приложение в статус In production. В статусе Testing войти могут не больше 100 вручную добавленных пользователей, а выданный доступ истекает через 7 дней ([справка Google Cloud](https://support.google.com/cloud/answer/15549945?hl=en)). Область `drive.file` не относится к чувствительным; нужна ли проверка приложения, покажет консоль.
5. Создать OAuth-клиент «Web application» с разрешёнными адресами `http://localhost:5173` и адресом сайта на GitHub Pages.
6. Создать API-ключ для Picker и ограничить его этим API и адресами сайта.
7. Перед этапом 6 создать OAuth-клиент «Desktop app» для MCP-сервера.
8. Записать значения в `.env.local` и в переменные репозитория GitHub: `VITE_GOOGLE_CLIENT_ID`, `VITE_GOOGLE_API_KEY`, `VITE_GOOGLE_APP_ID`.
9. Включить GitHub Pages с публикацией через GitHub Actions.
